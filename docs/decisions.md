# Decisions

Defaults chosen where the kickoff left things open. Each one is cheap to change; the "where" column says how.

| # | Decision | Why | Where to change |
|---|----------|-----|-----------------|
| 1 | Vite `base` comes from the `BASE_PATH` env var; GitHub Actions sets it to `/<repo>/`, local dev uses `/`. | Keeps local dev at `http://localhost:5173/` and still works on GitHub Pages. For a custom domain set the `BASE_PATH` repository variable to `/`. | `vite.config.ts`, `.github/workflows/deploy.yml` |
| 2 | Sign-in codes: both the "Confirm signup" and "Magic Link" email templates render `{{ .Token }}`. | Supabase sends "Confirm signup" on a user's first sign-in and "Magic Link" afterwards; both must show the code or first-time users get a link. | `supabase/config.toml` (local), Auth → Email Templates (hosted) |
| 3 | Keep-alive runs Monday and Thursday 06:00 UTC and calls `public.ping()` via PostgREST. | Twice a week leaves slack if one run fails; an RPC guarantees a real query reaches Postgres. | `.github/workflows/keepalive.yml` |
| 4 | CI runs lint, typecheck, Vitest, a build with placeholder env, and the pgTAP suite on a throwaway local Supabase. | Database rules are the core of the app; they must be tested on every PR, not just locally. | `.github/workflows/ci.yml` |
| 5 | Placeholder PWA icons are generated by `scripts/make-icons.mjs` (CETIN blue background, white desk, red seat). | No design assets yet; the script needs no image libraries. Replace the PNGs in `public/` with real artwork any time. | `public/`, `npm run icons` |
| 6 | UI strings live in `src/strings.ts` as one typed object; error codes raised by the database map 1:1 to `strings.errors`. | A Czech version becomes a second object with the same shape. | `src/strings.ts` |
| 7 | Theme uses CETIN brand colours (CETIN Blue `#300091`, red `#f12e49`, digital background palette) and Avenir → Arial. | Internal CETIN tool; follows the brand guide without embedding the logo. | `src/index.css` |
| 8 | Supabase CLI is a dev dependency (`npm run db:*`), not a global install. | Same CLI version for everyone and in CI. | `package.json` |
| 9 | Function parameters are prefixed `p_` (`book_seat(p_seat_id, p_date, p_slot)`). | Avoids ambiguity with column names inside plpgsql; the kickoff's `book_seat(seat_id, date, slot)` is the same contract. | `supabase/migrations` |
| 10 | `book_seat` accepts `'FULL'` as well as `'AM'`/`'PM'` and books both halves in one atomic call (`returns setof bookings`). | A full day is "both halves"; one call keeps it all-or-nothing and saves a round trip. | `book_seat` |
| 11 | Errors are raised as `raise exception '<code>'` (SQLSTATE `P0001`); the message is the code and `strings.errors` maps it to text. | One place to translate; the UI never shows raw database text. | `src/strings.ts`, `src/lib/errors.ts` |
| 12 | Email domain enforcement is a `before insert` trigger on `auth.users`, not an Auth hook. | Works with zero dashboard configuration and cannot be forgotten when a project is recreated. The "Before User Created" hook is an equivalent alternative. | `enforce_email_domain()` |
| 13 | `settings.allowed_email_domains` is an array; an empty array allows every domain. `get_allowed_email_domains()` is callable by `anon` so the sign-in form can warn before sending a code. | Cheap flexibility; the domain list is not secret. | `settings`, `get_allowed_email_domains()` |
| 14 | Display names are derived from the email local part (`jane.doe` → "Jane Doe"); users can rename themselves on My bookings; admins can fix names in the dashboard. | Nobody has to fill a form on first sign-in. | `display_name_from_email()`, `MyBookings.tsx` |
| 15 | Colleagues see only `profiles.user_id` and `display_name` (column-level grants); `role` and `email` are not readable through the API. `is_admin()` answers the role question. | Spec: display name only. | migration "Privileges" |
| 16 | Admins manage seats, floors and offices through RLS policies on `is_admin()`; roles change only via `admin_set_role()` or the dashboard. | Lets a future admin screen work without new migrations while keeping role escalation impossible for users. | migration "Row level security" |
| 17 | `public.bmd_now()` is the single source of "now"; pgTAP tests `create or replace` it to freeze time. | Deterministic tests of window edges and deadlines without test hooks in production code. | `supabase/tests/*.sql` |
| 18 | Each pgTAP file carries its own tiny helper (`tests_tmp.create_user`, `tests_tmp.login`) and creates its fixtures inside the rolled-back transaction. | `supabase test db` runs each file in a separate session, so shared helpers would need to live in a migration. | `supabase/tests/*.sql` |
| 19 | `seed.sql` is idempotent (`on conflict do nothing`) with fixed office/floor ids. | Safe to run `db push --include-seed` more than once. | `supabase/seed.sql` |
| 20 | Seat tiles are computed by a pure `seatView()` with Vitest coverage; the database remains the authority on every tap. | The grid is the heart of the UI and has many states (free, partly, mine, taken, held). | `src/lib/seatState.ts` |
| 21 | Realtime refreshes by invalidating React Query caches (bookings, releases, seats, profiles) rather than patching rows. | Simple and always consistent; 10–15 users produce negligible traffic. | `src/hooks/useRealtime.ts` |
